# RANKCRACKERS — CROSS-FEATURE AUTHORITY, EVIDENCE AND STUDENT-STATE CLOSURE CONSTITUTION

Document ID: RC-CROSS-FEATURE-001  
Version: 1.0 — WORLD-CLASS SYSTEM CLOSURE / CANONICAL-FEATURE-RECONCILIATION / IMPLEMENTATION-NOT-CLAIMED  
Status: Canonical cross-feature architecture baseline; NOT runtime implementation proof  
Scope: Canonical Syllabus → DigiBook/Taught → Crucible → Test Arena → Rank Radar → Revision Desk → PYQ Vault → Sacred Archive → Career Signals  
Founder law: No feature may silently become authority for a fact owned by another feature.

---

## 1. Purpose

RankCrackers now has individually strong feature constitutions. The remaining architectural risk is not lack of features; it is **cross-feature authority drift**.

This constitution closes the system-level questions:

- Who owns each kind of truth?
- Which feature may derive what?
- Which evidence may cross a boundary?
- Which histories are mutable versus append-only?
- What happens when upstream truth changes?
- What may influence Student action without becoming academic truth?
- What must fail closed?
- What must never be inferred?

The target is one coherent learning-and-opportunity system, not a set of independent intelligent-looking screens.

---

## 2. Supreme system laws

**OFFICIAL AUTHORITY DEFINES EXTERNAL TRUTH.**

**SYLLABUS = WHAT.**

**SUBJECT TEACHER / PEDAGOGY = HOW.**

**DIGIBOOK = ACTUAL TAUGHT MATERIAL.**

**ASSESSMENT = BOUNDED BY VERIFIED + ACTUALLY TAUGHT CONTENT.**

**PYQ != SYLLABUS AUTHORITY.**

**CRUCIBLE != FORMAL MAJOR TEST AUTHORITY.**

**TEST ARENA = GOVERNED FORMAL ASSESSMENT + QUALIFIED COMPETITIVE EVIDENCE.**

**RANK RADAR = DOWNSTREAM COMPETITIVE INTERPRETATION, NOT A SECOND RANK AUTHORITY.**

**REVISION DESK = RECOVERY ORCHESTRATION, NOT MASTERY AUTHORITY.**

**SACRED ARCHIVE = RECONSTRUCTABLE STUDENT ACADEMIC MEMORY, NOT LIVE TRUTH AUTHORITY.**

**CAREER SIGNALS = VERIFIED OPPORTUNITY INTERPRETATION, NOT SELECTION PREDICTION.**

**DOCUMENTED != IMPLEMENTED.**

## 6. Version spine

Every derived truth must be reconstructable from the versions that governed it.

Minimum principle:

```text
DERIVED_STATE
= INPUT_IDENTITIES
+ INPUT_VERSIONS
+ POLICY_VERSION
+ GOVERNED_TIMESTAMP
+ OUTPUT
```

If an upstream version changes, the system must choose explicitly among:

UNCHANGED  
RECOMPUTE  
SUPERSEDE  
INVALIDATE  
HOLD_FOR_REVIEW.

Silent mutation is prohibited.

---

## 7. Time semantics

Use governed/server time for authoritative deadlines, eligibility evaluation timestamps, assessment submissions, ranking snapshots and evidence chronology.

Client local time may format display but must not decide authoritative state.

Historical events preserve their original governed timestamp.

**TODAY'S CLOCK != HISTORICAL TRUTH.**

---

## 8. Current truth versus historical truth

Current features answer **what is true/actionable now**.

Sacred Archive answers **what was recorded as true/actionable then, under which authority/version**.

When authority changes:

```text
THEN: old valid snapshot remains reconstructable
NOW: current governed state reflects new authority
```

No current engine should query an old Archive snapshot and treat it as current truth without revalidation.

## 10. Taught boundary

Verified syllabus is necessary but not sufficient for ordinary academic assessment eligibility.

The normal assessment boundary is:

```text
VERIFIED
AND CURRENT
AND TAUGHT
AND KNOWLEDGE-BOUNDARY VALID
AND QUESTION-TRACEABLE
```

PYQ historical browsing may expose historical evidence outside current taught scope, but it does not thereby authorize current assessment or weakness.

Career Signals is outside the taught boundary because official job eligibility is not an academic mastery claim.

---

## 11. Question integrity across features

A question used by Crucible, Test Arena, PYQ Vault or Revision Desk must not fork into independent truth copies.

Question Repository owns canonical identity/version/dependency.

Feature records reference the question/version and preserve feature-specific evidence:

Crucible -> practice attempt  
Test Arena -> formal attempt  
PYQ Vault -> official historical appearance + Student interaction  
Revision Desk -> recovery action/verification.

A corrected question or answer authority may trigger bounded re-evaluation; old evidence remains auditable.

---

## 12. Crucible boundary

Crucible owns the 98-day rotating practice/recovery-oriented assessment cycle.

Canonical law:
- seven 14-day phases;
- Micro/Macro remain in the cycle;
- Day 13 Rebuild;
- Day 14 Macro;
- Day 98 rolls to next Day 1;
- Student cumulative history does not reset.

**Major Test is not part of Crucible.**

Any legacy Day99/Day100 Major or 100-day tactical semantics are supersession candidates and must not regain authority through implementation convenience.

Crucible may produce qualified readiness/attempt evidence for Test Arena eligibility but cannot self-authorize a formal Major.

---

## 13. Test Arena boundary

Test Arena owns formal governed assessment.

Major eligibility is earned from evidence, not fixed Crucible day numbers.

Full Test is distinct from Major and requires its own maturity/readiness gate.

Test Arena owns:
- formal attempt identity;
- form/blueprint;
- score;
- scoring policy;
- qualified ranking/percentile evidence;
- regrade/supersession.

Multi-paper/stage exams retain separate official identities unless official merit law authorizes aggregation.

No arbitrary tie-breaking may fabricate unique ranks.

---

## 14. Ranking evidence contract

Rank-like output must declare what it is:

RAW_MARKS  
PERCENTAGE  
WITHIN_FORM_PERCENTILE  
EQUATED_SCORE  
BENCHMARK_REFERENCE_PERCENTILE  
LIVE_COHORT_PERCENTILE  
RANK.

Different labels are not interchangeable.

Cross-form competitive comparison requires sufficient comparability/equating evidence.

Small cohorts must not produce fake precision.

Historical rank snapshots are immutable context; current Rank Radar may interpret newer evidence without rewriting old snapshots.

---

## 15. Rank Radar boundary

Rank Radar consumes qualified competitive evidence.

It may answer:
- where the Student currently stands under a qualified benchmark;
- how position is changing;
- readiness interpretation;
- evidence-backed drivers;
- next-best routing hints.

It cannot:
- rescore Test Arena;
- create a second rank;
- create academic weakness from rank alone;
- predict official government selection;
- mutate Revision Desk recovery;
- treat archived rank as live.

**RANK DROP != ACADEMIC WEAKNESS.**

---

## 16. Revision Desk boundary

Revision Desk follows:

**DETECT -> DIAGNOSE -> REPAIR -> VERIFY.**

Detection is not diagnosis.

Repair activity is not recovery proof.

Multiple related evidence events may compress into one explainable recovery objective while preserving provenance.

Potential inputs:
- DigiBook/Taught evidence;
- Crucible;
- Test Arena;
- PYQ interaction;
- Rank Radar bounded routing hint;
- governed mastery/retention signals.

Rank alone never creates knowledge deficit.

Untaught/stale/invalidated knowledge cannot become ordinary current weakness.

---

## 17. Recovery feedback law

A recovery loop is valid only when:

1. source evidence is qualified;
2. target knowledge is current/taught where required;
3. diagnosis is evidence-bounded;
4. repair action matches the supported cause/need;
5. completion evidence is recorded;
6. later verification establishes recovery;
7. any mastery/retention update comes from its owning governed engine.

**REPAIR_EVIDENCE != RECOVERY_EVIDENCE.**

**REVISION_COMPLETION != MASTERY.**

---

## 18. PYQ Vault boundary

PYQ Vault is the Student projection of verified historical exam evidence.

It owns neither syllabus nor question canonical truth.

It may expose:
- paper/shift/year appearance;
- official answer-key chronology;
- canonical question mapping;
- RankCrackers reviewed solution;
- Student save/attempt/revisit state.

Historical-only PYQ content cannot bypass current taught boundaries to become current academic weakness.

PYQ frequency is descriptive historical evidence, not a future-question guarantee.

---

## 19. Sacred Archive boundary

Sacred Archive stores/projections qualified meaningful Student history.

It does not become a second database authority for every feature.

It may preserve:
- formal assessment snapshots;
- Crucible meaningful events;
- recovery lifecycle milestones;
- PYQ Student interactions where policy qualifies them;
- rank snapshots;
- material Career Signals events;
- authority-change/supersession context.

It must preserve THEN/NOW distinction.

**REPLAY != OVERWRITE.**

A replay/retry creates new evidence; it does not mutate the historical attempt.

Routine clicks need not become immutable academic history.

---

## 20. Career Signals boundary

Career Signals consumes:
- verified recruitment evidence;
- canonical Mission identity;
- governed Secondary Profile facts.

It resolves:
- opportunity relevance;
- official rule-by-rule eligibility;
- applicable posts/vacancies/relaxations/fees/dates;
- missing profile facts;
- mission-specific official alerts.

It does not consume rank/test/mastery as official eligibility.

Preparation context, if later shown, must remain explicitly RankCrackers guidance.

**ELIGIBLE != SELECTED.**

**VACANCIES != SELECTION CHANCE.**

---

## 21. Secondary Profile boundary

Secondary Profile owns Student personal facts used for Career Signals.

A consumer may request a missing fact but may not silently mutate it.

Missing material data produces an explicit unknown/action state, not guessed eligibility.

Delivery-channel completeness is separate from eligibility completeness.

Example:
"Add email to receive email alerts" != "Eligibility incomplete."

## 23. Projection law

Student-facing screens are projections of authority, not authority themselves.

A projection may be rebuilt.

Therefore:
- Dashboard card != source of truth;
- Archive timeline != source of truth;
- Rank Radar card != ranking authority;
- Career Signal card != recruitment authority;
- Revision card != mastery authority.

Projection corruption must not corrupt upstream truth.

## 24. Fail-closed matrix

| Condition | Required behavior |
|---|---|
| Official evidence missing | no authoritative official claim |
| Mission identity ambiguous | hold; no cross-mission merge |
| Syllabus stale | block affected derived academic truth |
| Taught evidence absent | no ordinary current assessment/weakness claim |
| Question version unresolved | block affected scoring/recovery |
| Ranking comparability unproven | no cross-form rank claim |
| Recovery cause unproven | CAUSE_NOT_ESTABLISHED / evidence gathering |
| Recruitment profile fact missing | MORE_INFORMATION_REQUIRED |
| Recruitment source stale | stale/superseded hold |
| Archive unavailable | live authority continues; history projection degrades honestly |
| Downstream feature unavailable | upstream authority remains intact |

## 25. No circular authority

Forbidden loops include:

Rank Radar -> Revision -> completion -> synthetic Rank Radar improvement.

Career Signals -> Rank Radar -> selection probability -> Career Signals priority.

Archive -> old score -> current Test Arena result.

PYQ frequency -> syllabus priority -> current syllabus authority.

Revision completion -> mastery without governed mastery evidence.

Dashboard engagement -> academic eligibility.

Any feedback loop must return through the actual owning authority and new qualified evidence.

---

## 26. Cross-feature psychology law

The system must not turn uncertainty into pressure.

Forbidden:
- fake rank precision;
- fake selection chance;
- shame from overdue recovery;
- red-alert overload;
- "weak student" identity labels;
- vacancy/salary bait;
- arbitrary streak pressure;
- false urgency.

Required:
- why this?
- what evidence?
- what is known?
- what is unknown?
- what action is useful?
- what will count as resolved/recovered/current?

---

## 27. Privacy partition

Academic weakness, attempts, rank snapshots, recovery, profile facts and opportunity eligibility are private Student data.

Cross-feature sharing follows minimum-necessary data.

Examples:
- Career Signals does not need Revision Desk weakness to decide official eligibility.
- Rank Radar does not need DOB/category to compute academic competitive evidence unless an explicitly governed benchmark requires it.
- Sacred Archive may reference sensitive events but must not become a public feed.
- Founder/admin access must be governed and auditable.

Retention/export/deletion must respect product/legal policy without falsifying historical lineage for retained records.

---

## 28. Cross-mission isolation

Every mission-bound event must bind MissionID.

No title matching may merge:
- JEE and NEET;
- RAS and another state service;
- annual recruitment event and permanent Mission;
- same post name under different authorities.

Cross-mission aggregate analytics, if ever allowed, must be explicitly derived and cannot mutate mission-local truth.

---

## 29. Offline and cache law

Offline projections may be shown only with freshness/integrity semantics.

Client cache cannot author:
- official currentness;
- eligibility;
- formal score;
- rank;
- mastery;
- recovery resolution;
- recruitment deadline truth.

Queued Student actions must be idempotent and version-aware on reconciliation.

---

## 30. Supersession, not erasure

When governed truth changes:

- old official document remains evidence;
- old assessment remains historical;
- old rank snapshot remains historical;
- old eligibility evaluation remains historical;
- new version supersedes current interpretation.

Delete/retention policy is a separate governance concern.

**CORRECTION != HISTORY REWRITE.**

## 32. Runtime reconciliation classes

Every existing artifact encountered during implementation audit must be classified:

**KEEP** — aligned and authoritative.  
**REFINE** — correct ownership, incomplete behavior.  
**MERGE** — duplicate concepts should converge without losing evidence.  
**SUPERSEDE** — replaced by later canonical architecture; preserve migration/audit context.  
**DEPRECATE** — no longer part of target runtime; deletion requires separate authorization.  
**FOUNDER_DECISION_REQUIRED** — cannot be resolved technically.

No artifact is deleted merely because a constitution supersedes it.

## 39. Closure verdict

The individual canonical feature constitutions are compatible at the architecture level **provided this authority ledger and boundary law govern reconciliation**.

The system target is:

```text
VERIFIED TRUTH
-> TAUGHT TRUTH
-> QUALIFIED PRACTICE EVIDENCE
-> FORMAL ASSESSMENT EVIDENCE
-> COMPETITIVE INTERPRETATION
-> EVIDENCE-GOVERNED RECOVERY
-> RECONSTRUCTABLE ACADEMIC MEMORY

AND, IN PARALLEL:

VERIFIED GOVERNMENT OPPORTUNITY
+ GOVERNED STUDENT PROFILE
-> TRANSPARENT ELIGIBILITY INTERPRETATION
-> PERSONALIZED CAREER SIGNAL
```

The two branches may coexist in one Student product without contaminating each other's authority.

**ONE FACT -> ONE CANONICAL OWNER.**  
**MANY CONSUMERS -> EXPLICIT VERSIONED CONTRACTS.**  
**EVERY DERIVATION -> TRACEABLE EVIDENCE.**  
**EVERY CORRECTION -> SUPERSESSION, NOT SILENT HISTORY REWRITE.**  
**EVERY UNKNOWN -> HONESTLY UNKNOWN.**  
**EVERY STUDENT ACTION -> EXPLAINABLE PURPOSE.**

**ARCHITECTURE CLOSED != RUNTIME RECONCILED.**  
**RUNTIME RECONCILED != DEPLOYED.**  
**DEPLOYED != VALIDATED.**
