# RankCrackers — PYQ Acquisition, Review & Delivery SOP v1.0

## End-to-end flow
Authority Watch → Official Evidence → Mission Candidate → Founder Acceptance → Mission Authority → Effective Examination Blueprint → Effective Syllabus/OSA → DSD/Atomic Verification → PYQ Discovery → Paper Acquisition → Question Appearance Extraction → Final-Key Acquisition → Exact Answer Mapping → Canonicalization → Syllabus/Atom Mapping → Review → Central Question Repository → DigiBook/Crucible/Test Arena Projection.

## Acquisition order
1. Search competent authority official archives/pages/documents.
2. Acquire original question paper when available.
3. Identify exact cycle, event, stage, component, date, session/shift, language and booklet/series/set as applicable.
4. Acquire latest effective Final or Revised Final key.
5. Hash and retain source evidence before transformation.
6. Extract appearances without normalizing away official identifiers.
7. Map key only to exact compatible appearance.
8. Canonicalize duplicates only after equivalence is proven.
9. Map to syllabus/DSD atoms without allowing PYQ content to expand syllabus.
10. Review and publish eligible projections.

## When final official key is unavailable
The question may remain official if its official paper provenance is proven. Answer authority remains OFFICIAL_ANSWER_NOT_ESTABLISHED or OFFICIAL_KEY_RELEASED_NOT_ACQUIRED. RankCrackers may produce an independently reviewed solution labelled RANKCRACKERS_VERIFIED_NONOFFICIAL. If official evidence later appears, compare automatically; mismatch becomes ANSWER_CONFLICT_REVIEW_REQUIRED.

## Commercial compilations
10/15/20-year books/PDFs are discovery and reconstruction sources only. Each recovered question carries its own provenance status. Never bulk-promote a compilation to official PYQs. Memory-based/coaching-only material remains nonofficial.

## Deleted/dropped questions
Preserve the question and official disposition. Do not treat it as an ordinary wrong-answer item or silently remove it from historical evidence. Student scoring/practice behavior must follow explicit product rules while retaining official history.

## Student delivery constitution
The backend Question Repository is not exposed as a database browser by default.
- DigiBook: contextual topic practice and relevant PYQs after/alongside taught material.
- Crucible: mastery/adaptive practice from verified+taught scope.
- Test Arena: sectional/full/mock/historical-paper experiences.
- Optional future PYQ Explorer: lightweight year/event/paper/subject discovery without leaking backend normalization.
Questions are referenced by canonical IDs; they are not duplicated across products. Attempt history is projection-specific.

## Taught-content boundary
Assessment questions used for scored learning must obey verified syllabus + taught-content authority. A PYQ outside current scope may remain historical evidence but must not bypass the taught-content gate.

## Review gates
Source gate → identity gate → extraction gate → answer-authority gate → canonicalization gate → syllabus-mapping gate → solution-quality gate → student-projection gate.

## Minimum acceptance tests
Reject/flag: wrong exam-year match; wrong stage/paper; wrong shift; wrong booklet/set; option-order mismatch; Question-ID mismatch; provisional key used as final; superseded final used after revised final; dropped question scored normally; commercial answer labelled official; fuzzy dedupe without proof; historical PYQ expanding current syllabus; missing evidence hash/provenance; duplicate physical copies; Student UI exposing internal normalization; untaught content entering Crucible/Test Arena; later official key conflicting with RankCrackers answer without review.
