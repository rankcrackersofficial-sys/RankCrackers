# RANKCRACKERS — SACRED ARCHIVE IMMUTABLE ACADEMIC MEMORY CONSTITUTION

Document ID: RC-SACRED-ARCHIVE-001
Version: 1.0 — WORLD-CLASS ACADEMIC MEMORY / FORENSIC-AUDIT-GROUNDED / FOUNDER-DIRECTION-CONSOLIDATED
Status: Canonical architecture baseline for implementation planning; NOT runtime implemented
Canonical student-facing name: Sacred Archive
Authority: Subordinate to each source domain's canonical authority. Sacred Archive preserves and projects history; it never becomes a second academic authority.
Conflict rule: CURRENT SOURCE AUTHORITY owns current truth. SACRED ARCHIVE owns durable historical evidence/projection of what was true, done, released or observed at a specific governed time.

## 1. Founder-level product verdict
The independent product need is justified, but the existing runtime is not the product.

Forensic audit proves two conflicting current surfaces:
- dashboard card labelled SACRED ARCHIVE is fail-closed and routes to DigiBook;
- The Archive screen is a live mission_realms asset browser.

Neither is a canonical student academic archive.

The world-class product is therefore defined as:

**Sacred Archive = the student's immutable, mission-scoped academic memory and evidence timeline.**

It answers:
WHAT happened?
WHEN did it happen?
UNDER WHICH mission/content/question/scoring/ranking policy version?
WHAT evidence supported it then?
WHAT changed later?
CAN the historical state be reconstructed without rewriting the past?

## 2. Non-negotiable distinction
Sacred Archive is not DigiBook, official-document storage, PYQ Vault, Question Repository, Crucible, Test Arena, Revision Desk, Rank Radar, leaderboard, achievement cabinet or backup folder.

It is a governed historical projection over those source authorities.

ARCHIVE != SOURCE OF TRUTH FOR CURRENT STATE.
HISTORY != CURRENT AUTHORITY.
SNAPSHOT != LIVE RECOMPUTATION.

## 6. Academic Memory Event
Canonical historical unit is AcademicMemoryEvent.

Every event binds, as applicable:
ArchiveEventID, StudentID, MissionID, sourceDomain, sourceEventID, eventType, occurredAt authoritative/server time, recordedAt, source policy/model version, source object IDs/versions, content/question/answer versions, assessment/form/attempt/result IDs, Taught Boundary fingerprint where academically material, rank/cohort snapshot reference where applicable, revision/recovery references where applicable, provenance/evidence references, supersedes/supersededBy, integrity/hash support, visibility class and schema version.

Not every event requires every field. Inapplicable dimensions remain null; never fabricate them.

## 7. Append-only historical law
Historical academic facts are append-only/supersession-based.

Never silently mutate original submitted answer, original score release, original rank snapshot, original answer authority used, original question/content version, original recovery decision or original policy version.

Corrections create new events linked to prior events.

Example:
RESULT_RELEASED(v1)
-> REGRADE_TRIGGERED
-> RESULT_SUPERSEDED(v1)
-> RESULT_RELEASED(v2).

The Archive can show the latest effective historical interpretation while preserving the original chain.

## 8. Event ledger versus projection
World-class design separates immutable/append-only event evidence from read-optimized Student projections.

Archive UI must not join every operational collection ad hoc and call the result history.

A governed projection worker/service builds mission-scoped timeline views from qualified source events.
Projection can be rebuilt. Source evidence/history cannot be fabricated by projection.

## 9. Historical reconstruction contract
A historical item is reconstructable only when enough evidence exists to reproduce its material meaning at that time.

For assessment history this may require mission/exam identity, paper/form identity, question appearances/versions, submitted answers, answer/scoring policy versions, duration/timing evidence, result release, regrade history and rank/cohort snapshot where shown.

For teaching/recovery history it may require Taught projection/version, knowledge identity/version, recovery source, repair/recovery evidence and policy version.

If exact reconstruction is impossible, UI states PARTIAL_HISTORICAL_RECORD or RECONSTRUCTION_NOT_AVAILABLE.

Never display a current question/content/rank as if it were the historical version.

## 10. Time-travel truth
Sacred Archive has two explicit semantic views:

**THEN** — what the governed evidence said at the historical point.
**NOW** — optional current status/correction, clearly separated.

Example:
THEN: Official answer authority v1, score 162.
NOW: Revised official key superseded v1; governed regrade score 166.

The past is not erased by the correction.

## 11. Mission-scoped learning timeline
Archive is organized primarily around the student's mission history, not a global mixed feed.

Possible event families:

Cross-mission aggregate views may exist only as navigation/summary and must preserve mission identity.
Same topic label across missions never establishes shared historical identity.

## 12. Crucible memory
Eligible archived Crucible evidence may include Micro attempts/results, Macro attempts/results, Rebuild events, phase/cycle provenance and qualified learning-state transitions.

Day98 -> Day1 does NOT reset or erase Archive history.
Cycle identity remains provenance.
Archive cannot alter current Crucible state.

## 13. Test Arena memory
Archive preserves released historical Test Arena evidence with exact benchmark/form/policy context.

Historical rank/percentile is a SNAPSHOT, not a live query against today's cohort.
A changed cohort/ranking policy cannot silently rewrite an old displayed rank.

Regrades append superseding result/rank events.
Old snapshots remain auditable.

## 14. PYQ boundary
Official historical exam evidence belongs to PYQ authority/PYQ Vault.
Sacred Archive records the student's interaction history with that evidence.

Thus:
OFFICIAL PYQ HISTORY != STUDENT PYQ HISTORY.

Archive may record viewed/saved/attempted historical paper/question, result/revisit/recovery references, but preserves QuestionAppearance and answer-authority versions.
It must not duplicate official PYQ into a second mutable archive bank.

## 15. Revision Desk memory
Revision Desk owns current debt/recovery orchestration.
Sacred Archive preserves significant historical recovery events: debt created, repair performed, verification outcome, resolved, reopened and superseded.

Archive cannot mark current debt resolved.
A historical "recovered" state is not automatically today's mastery state.

## 16. Rank Radar memory
Rank Radar owns current competitive interpretation.
Sacred Archive may preserve governed RankRadarSnapshot references.

Historical competitive position is displayed with benchmark, cohort/reference population, denominator where valid, policy/model version, timestamp and qualification/confidence.
It is never recomputed silently as current competitive truth.

## 17. DigiBook/Taught memory
DigiBook/Taught Authority owns current taught truth.
Archive may preserve significant historical taught/projection milestones and exact version references necessary to explain later assessment/recovery evidence.

Archive is not an old-DigiBook browser by default.
Historical content is surfaced only when academically meaningful and permitted.

## 18. Official evidence boundary
Official notifications, syllabus files, question papers, keys and corrigenda remain in official evidence governance.

Sacred Archive references their immutable IDs/versions when needed to explain a student's history.
It does not become another official document repository.

The existing ArchiveScreen signed-asset browser must therefore not be treated as the canonical Sacred Archive merely because it downloads official assets.

## 19. Replay and retry
Opening history is read-only.

If Student chooses Try Again from an archived item:
- original record remains immutable;
- a NEW governed practice/revision/historical-replay attempt is created in the owning domain;
- new attempt links originArchiveEventID;
- new result returns to Archive as a separate event.

REPLAY != OVERWRITE.

## 20. Personal progress, not fake trophies
Sacred Archive may show evidence-backed milestones/personal bests when rules are governed and reproducible.

It must not fabricate XP, streaks, badges, trophies, legend status, rank improvement or personal best.
Gamification is subordinate to evidence integrity and healthy psychology.

## 21. Student reflection
Archive may support private student reflection/notes as a separate learner-owned layer.

A reflection never mutates historical evidence.
Notes bind ArchiveEventID/StudentID and have their own edit history/privacy policy if implemented.

## 22. Evidence density and progressive disclosure
World-class Archive must not dump raw logs.

Student-facing hierarchy:
1. Mission journey summary
2. Meaningful timeline
3. Event card
4. Evidence details drawer
5. Exact source/version/provenance on demand

Routine low-value telemetry can remain hidden while still auditable.
Meaningful-event policy must be versioned.

## 23. Explainability

WHAT happened?

IN WHICH MISSION?
WHAT was the scope?
WHAT was the result?
UNDER WHICH rules/version?

WHY?

If data is incomplete, uncertainty is visible.

No cross-student archive reads without explicit governed authorization.
Share/export policy is pending and cannot be inferred from authenticated mission timeline reads.

## 25. Retention, deletion and export
Exact legal/product retention durations are PENDING POLICY.

Architecture laws:
- operational deletion must not silently corrupt retained evidence chains;
- account deletion/export requirements must be explicitly designed before production;
- legal/privacy obligations override sentimental "permanent archive" branding;
- immutable means tamper-resistant historical semantics within governed retention, not legally undeletable forever.

## 26. Integrity
Where material, archived projections bind source identifiers, schema versions and integrity/hash support.

Projection worker is idempotent.
Duplicate source events do not create duplicate timeline facts.
Out-of-order events are reconciled by source identity/version, not client arrival order.
Client clock is never historical authority.

## 31. Cross-domain event intake

No generic scraper over mutable collections.

This prevents Sacred Archive from becoming a fragile mega-join.
